01 / The journey

Learn the model.
Engineer the system.

The questions evolved from “how does a model learn?” to “how can an agent help an engineer do meaningful work?”

  1. 01 / LEARN

    Build from fundamentals.

    Hands-on learning with Andrej Karpathy's makemore (external) made model behavior tangible, beyond the API surface. That curiosity remains part of how I approach engineering.

  2. 02 / BUILD

    Connect models to workflows.

    Since 2025, professional agent development has included an initial harness, multi-agent orchestration, federated MCP tools, a gateway and skills, plus routing, retrieval, and evaluation components that I built.

  3. 03 / EVALUATE

    Make improvement inspectable.

    Use bounded review loops, explicit acceptance decisions, and persisted outputs. Test context and routing choices against workflow outcomes rather than treating a fluent answer as proof.

  4. 04 / ENABLE

    Grow the work with a team.

    The team extended retrieval and routing and built the private inference stack. Together, the work supports live networking / web testing and monitoring agents—not just isolated demos.

The through-line: curiosity at the model level, discipline at the system level, and usefulness at the human level. This is shared engineering work, not a claim of sole ownership of the entire stack.

Control & observability

Keep boundaries explicit.

RBAC role permissions constrain actions. Selective human escalation through email, chat, or Slack keeps decisions with the right people.

  • OpenTelemetry routing and usage signals
  • Permission-aware tool access; no bypass
  • Explicit latency and token-budget tradeoffs
Inside the review loop: ratchet, frontier judge, and Dream rounds
  1. Execute an inner DAG
  2. Review with a frontier judge
  3. Refine within budget
  4. Persist accepted outputs
  5. Revisit reusable memory

A budget-bounded ratchet reviews an inner directed acyclic graph (DAG) of work. A frontier-model judge informs enrichment of context or parameters for subsequent attempts. Accepted outputs are persisted rather than treating every attempt as reusable knowledge.

Dream rounds revisit accumulated memory to promote reusable skills or retire memory that should not be retained. These are workflow and memory refinements—not model-weight training. Judge acceptance is not a guarantee of correctness.
